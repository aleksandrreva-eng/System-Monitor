# Project Documentation: System Resource Monitor

## 1. Overview
**System Resource Monitor** is a high-performance, cross-platform desktop application designed to provide real-time monitoring of system resources (CPU, RAM, GPU, Disk, and Network). It utilizes a hybrid architecture combining a modern web-based frontend (HTML/CSS/JS) with a robust Python backend for hardware interaction using PyQt6.

## 2. Technology Stack
*   **Programming Language:** Python 3.x
*   **GUI Framework:** PyQt6
*   **Frontend Rendering:** `QWebEngineView` (Chromium-based)
*   **Frontend Technologies:** HTML5, CSS3, JavaScript (Vanilla JS)
*   **Inter-process Communication:** Qt WebChannel (Bridge pattern for JS $\leftrightarrow$ Python communication)
*   **System Metrics Collection:** 
    *   `psutil`: Core system metrics (CPU, RAM, Disk, Network).
    *   `pynvml`: NVIDIA GPU monitoring.
    *   `amdsmi` / `pyadl`: AMD GPU monitoring.
    *   `pyintelgpu`: Intel GPU monitoring.

## 3. Architecture
The project follows a **Hybrid Desktop-Web Architecture** with a layered backend:

1.  **Presentation Layer (Frontend):** A web application rendered inside a `QWebEngineView`. It handles all UI animations, styling, and user interactions via JavaScript. The UI is served from a temporary local file generated by the backend to ensure cross-platform compatibility.
2.  **Communication Layer (Bridge):** The `bridge.py` module acts as a bidirectional gateway. Python methods are exposed to the JavaScript context using `@pyqtSlot`, allowing the frontend to request data or trigger actions in the backend. Data is exchanged primarily in JSON format.
3.  **Logic Layer (Backend):**
    *   **Providers (`providers/`):** Implements the **Provider Pattern**. Each hardware component (CPU, GPU, RAM, Disk, Network) has a dedicated provider class inheriting from a `BaseProvider`. This ensures modularity and scalability.
    *   **Stats Collector (`stats_collector.py`):** Aggregates data from providers, manages internal caching, and handles threshold-based alerting.
    *   **GPU Manager (`gpu_manager.py`):** Hardware abstraction layer for GPU initialization. It uses a plugin-based approach to detect and initialize NVIDIA, AMD, or Intel drivers gracefully.

## 5. Functional Modules

### `monitor/app.py`
The application bootstrap module. It initializes logging to `~/.monitor/logs/monitor.log`, configures High DPI scaling for modern displays, loads user settings, and launches the main window. It also enables remote debugging for the WebEngine via `chrome://inspect`.

### `monitor/main_window.py`
Manages the primary application window. Key features:
*   **Frameless UI:** Uses `FramelessWindowHint` and translucent backgrounds (`WA_TranslucentBackground`) for a modern, transparent look.
*   **System Tray Integration:** Allows the app to run in the background (minimizing to tray) rather than closing on exit.
*   **Dynamic HTML Loading:** Generates a temporary HTML file from the frontend assets to ensure local resource loading via `QUrl`.

### `monitor/bridge.py`
The "Brain" of the communication layer. It implements the `Bridge` class which:
*   Exposes Python methods as `@pyqtSlot` for JavaScript access.
*   Validates all incoming data from the frontend (e.g., settings validation).
*   Serializes complex system data into JSON strings for transmission to the UI.

### `monitor/stats_collector.py`
The engine responsible for telemetry collection. 
*   **Metric Gathering:** Aggregates data using the Provider registry.
*   **Alerting System:** Implements a threshold-based alerting mechanism (e.g., "CPU > 90%"). It uses `weakref` to store callbacks, preventing memory leaks when UI components are destroyed.
*   **Caching:** Implements internal caching for expensive operations (like CPU power or temperature polling) to minimize system overhead.

### `monitor/gpu_manager.py`
A hardware abstraction layer that detects and initializes GPU drivers. It supports:
*   **NVIDIA** via NVML.
*   **AMD** via AMDSMI or ADL.
*   **Intel** via pyintelgpu.
It provides a unified `GPUDevice` interface to the rest of the application, hiding vendor-specific complexities.

## 6. Key Features Summary
*   **Real-time Telemetry:** High-frequency updates for all major system components.
*   **GPU Agnostic:** Seamlessly switches between NVIDIA, AMD, and Intel hardware.
*   **Resource Efficient:** Uses caching and asynchronous patterns to ensure minimal CPU impact from the monitor itself.
*   **Modern UI/UX:** Leverages web technologies for a highly customizable and visually appealing interface.
*   **Robustness:** Extensive error handling and validation for both system calls and user-provided settings.
